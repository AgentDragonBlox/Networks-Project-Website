Ping + RTT

ping_rtt/ping.pysubprocess · re

ping(target, count=4) runs the operating system's own ping command, reads the round-trip time from each reply with one regular expression, and works out packet loss and min/avg/max RTT. display_results() prints the boxed report.

How it works

Build the command

Windows counts packets with -n. Linux and macOS use -c. platform.system() decides which one.

Run with a timeout

subprocess.run(…, timeout=30). If it times out or raises, the function returns a 100%-loss dict with an error message.

Regex the replies

time[=<]\s*(\d+(?:\.\d+)?)\s*ms matches time=20ms, time=20.5 ms and time<1ms. Summary lines don't match.

Do the maths

received = number of matches. loss = (count − received) / count × 100. min/avg/max are rounded to 2 decimals, or None if nothing came back.

Why count matches instead of reading the OS summary? The summary line differs between operating systems, and Windows counts “Destination host unreachable” replies as received. Counting real time= values gives the same answer everywhere. Try the “Destination host unreachable” scenario on Windows to see the difference.

pattern = r"time[=<]\s*(\d+(?:\.\d+)?)\s*ms"
matches = re.findall(pattern, output, re.IGNORECASE)
latency_values = [float(value) for value in matches]

received = len(latency_values)
packet_loss = ((count - received) / count) * 100

if latency_values:
    min_rtt = min(latency_values)
    avg_rtt = sum(latency_values) / len(latency_values)
    max_rtt = max(latency_values)
else:
    min_rtt = avg_rtt = max_rtt = None
