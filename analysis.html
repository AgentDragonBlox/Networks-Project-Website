Path Analysis

path_analysis/analyzer.pypython -m path_analysis

analyze_path(hops, jump_ms=50, loss_thresh=20) turns raw hop data into per-hop statistics and flags likely trouble spots. It accepts a TracerouteResult, a list of Hop objects, or plain dicts such as {"hop": 1, "ip": "10.0.0.1", "rtts": [2.1, 2.0, None]}.

How it works

analyze_hop()

Drops the None probes, then computes min, avg and max. Jitter is the population standard deviation (pstdev), and 0.0 with only one reply.

Latency delta

Each hop's avg minus the previous responding hop's avg. Silent hops are skipped, so they never break the chain.

Flag bottlenecks

A hop is flagged if Δ > jump_ms, or if it has partial loss of at least loss_thresh. 100% loss isn't flagged, because many routers simply ignore probes.

summary()

Prints a fixed-width table, the total and silent hop counts, the end-to-end RTT, the biggest jump, whether the destination was reached, and the flagged hops.

Rule 1: latency jump
s.delta_ms is not None and s.delta_ms > jump_ms
Rule 2: partial loss
0 < s.loss_pct < 100 and s.loss_pct >= loss_thresh

Reading the results. A negative Δ (a farther router answering faster than a nearer one) is normal. It comes from ICMP rate limiting or asymmetric routes. In the ICMP rate-limited router dataset, hop 4 is flagged for a jump, but hop 5 is fast again, which shows the delay was in how the router handled the probe and not on the path itself. Drag jump_ms to see how sensitive the detector is.

def analyze_path(hops, jump_ms=50, loss_thresh=20):
    if hasattr(hops, "hops"):
        hops = hops.hops
    stats = [analyze_hop(*_unpack(h)) for h in hops]

    prev = None
    for s in stats:
        if s.avg_rtt is not None:
            if prev is not None:
                s.delta_ms = s.avg_rtt - prev
            prev = s.avg_rtt

    # Fully silent hops (100% loss) are usually routers ignoring probes,
    # so only partial loss or a big latency jump counts as a bottleneck.
    bottlenecks = [
        s for s in stats
        if (s.delta_ms is not None and s.delta_ms > jump_ms)
        or (0 < s.loss_pct < 100 and s.loss_pct >= loss_thresh)
    ]
    return stats, bottlenecks
