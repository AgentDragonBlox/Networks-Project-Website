SDN Lab: POX + Mininet

sdn/netpath_controller.pysdn/multipath.pysdn/netprobe.pysdn/correlate.py

Mininet builds a real virtual network on this Linux machine: two hosts and five Open vSwitch switches, joined by three alternative paths. The switches have no forwarding logic of their own. The POX controller finds the topology, decides which path traffic takes and installs OpenFlow rules. Our socket-based app, netprobe, measures delay and loss with UDP probes, and the page correlates each measurement with the path POX chose.

Example mode. The lab isn't running, so a model of the same network answers instead: the same topology, link delays and loss, route policies, failover and controller log, but simulated numbers. Start POX and sudo python3 sdn/multipath.py --serve (see Run it on Linux), then choose Live lab.

How it works

Mininet builds the network

multipath.py creates h1, h2 and switches s1–s5 as Linux namespaces and Open vSwitch bridges. TCLink gives path A 2 ms links, path B 20 ms links and path C a link that drops 10% of packets.

POX discovers the topology

Each switch opens an OpenFlow connection to POX on port 6633. openflow.discovery sends LLDP out of every port to find the links, and hosts are learned from the port their first packet arrives on.

POX decides every path

A switch with no matching rule sends the packet to POX (packet-in). POX lists the loop-free paths, picks one by the route policy and installs a rule on each switch along it (flow-mod). Later packets never reach POX.

netprobe measures, we correlate

h1 sends numbered UDP datagrams to an echo server on h2. RTT, jitter and loss are joined with the path POX reports, so the extra delay or loss is attributed to the links that path doesn't share with the best one.

    What to point out. Path A and C have the same delay, but C loses about 19% of round trips: the 10% loss applies in each direction. Path B is clean but about 84 ms instead of 12 ms. The application can't see switches, yet once its measurements are joined with the controller's paths, the difference is pinned to exactly the links that path doesn't share. When s2–s4 fails, POX gets a port-status message, records which paths used the link, clears the flows and reroutes. The gap in the probe sequence is how long traffic was interrupted.
    

      
    Routed lab: what traceroute sees
    
      
    OpenFlow switches forward at layer 2 and never lower the TTL, so through the multipath lab traceroute would see a single hop. topology.py builds a second network with three Linux routers between the switches, so every router is a hop. The s3–r3 link adds 30 ms each way and the s4–h2 link drops 15% of packets, which gives path analysis a latency jump and partial loss to find.

    Everything stays on localhost. serve.py reads the controller's export from /tmp/netpath_topology.json and forwards the controls to multipath.py, which runs them in Mininet: route changes go through POX's policy file, links are failed with configLinkStatus, and probes run netprobe.py on h1. The full scripted experiment is sudo python3 multipath.py --auto. For the routed lab, stop the multipath lab and run sudo python3 topology.py --auto: serve.py picks up its traceroute.txt for the panel above.
